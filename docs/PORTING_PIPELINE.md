# PSP Forge porting pipeline

## Pipeline

1. **Intake:** record title, exact version, target PSP models, source availability and licence.
2. **Inventory:** scan directory structure, file sizes, extensions and likely engine clues.
3. **Feasibility gate:** classify as source-port candidate, engine reimplementation, asset-only research, or binary-only/high-risk.
4. **Profile:** define source engine, assets, PSP target, renderer, audio, input, filesystem, threading and memory budgets.
5. **Asset pipeline:** add one tested importer/exporter at a time. Never assume an extension uniquely identifies a format.
6. **Engine port:** compile portable game logic for the PSP toolchain and replace unsupported APIs.
7. **Render/audio/input:** implement PSP-specific adapters and establish performance budgets.
8. **Package:** generate EBOOT.PBP using PSPSDK tooling.
9. **Validate:** run automated checks, PPSSPP tests, then physical hardware tests.
10. **Report:** capture FPS, memory headroom, loading times, crashes, missing assets and known limitations.

## Milestones

- **M0, 1–2 days:** install PSPDEV/PSPSDK; build smoke test; verify EBOOT.PBP and run in PPSSPP.
- **M1, 2–5 days:** test Python inventory, preliminary feasibility output and profile validation.
- **M2, 1–2 weeks:** implement and test one open asset format pipeline.
- **M3, 2–6 weeks:** port a small open-source PC game with available source.
- **M4, game-dependent:** add reusable adapters for one engine.
- **M5, months or longer:** investigate a specific PS2 title; do not treat this as generic ISO conversion.

Timelines are estimates, not guarantees.

## Preliminary feasibility categories

- `source_candidate`: C/C++ source-like files found. This does not prove complete source is present.
- `binary_only`: PC executable detected, source not established.
- `binary_or_disc_only`: disc/image file detected; direct conversion is not supported.
- `unknown`: insufficient file clues. Manual review required.

These labels are heuristics, not a compatibility verdict.

## Acceptance criteria

- Python tests pass on a clean checkout.
- Analyser output is deterministic for a stable input directory.
- Profile validation rejects malformed JSON and missing required fields.
- PSP app builds using the installed PSPSDK.
- EBOOT.PBP is generated by PSPSDK, not created by renaming another executable.
- Smoke test boots in PPSSPP, then on target hardware.
- A real port demonstrates asset loading, rendering, input and audio.
- No proprietary game assets are committed.
- Each supported title has explicit hardware, performance and compatibility results.
